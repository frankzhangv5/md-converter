# 复制到微信公众号

> 在浏览器中把当前主题下的正文做成**带内联 style 的 HTML**，写入剪贴板，便于粘贴到公众号编辑器。依赖 [003](../003-markdown-html-converter/README.md) 的文档外壳与正文容器约定。

## Overview

公众号编辑器会丢掉外部 CSS 与 `class`，较稳定保留剪贴板里的 **内联 `style=`**。磁盘上的 HTML 把主题 CSS **内联**进 `<style id="md-theme">`（见 003），换肤不改标签；用户点击「复制到公众号」时，再按**当前已加载 CSS 的计算样式**临时内联，并做若干公众号兼容改写。

用户流程：

1. 转换 Markdown 为 HTML（默认启用复制能力；可用 `--no-copy` 关闭）
2. 用浏览器打开生成页（CSS / 脚本已内联，无需旁路文件）
3. 点右下角「复制到公众号」
4. 粘贴到公众号后台编辑器

换 `--theme`（或 `--css`）即换复制结果，无需另导一份 HTML。

## Design

### 页面约定

- 正文在 `#md-article` 内（由 003 规定）。
- 默认在文档中**内联**复制脚本（`<script id="md-copy-wechat-js">`）；`--no-copy` 时不写入。
- 脚本执行后在页面右下角挂载「复制到公众号」按钮；**不**改写磁盘上正文的 `style=`。
- 复制目标仅为 `#md-article` 的内容（不含按钮本身）。

### 复制结果应满足

对正文的一份克隆依次处理，最终输出一段可粘贴的 HTML（建议外包一层带根排版样式的容器），并附带纯文本后备：

1. **去掉文首标题**：删除正文根下第一个顶层 `h1`（公众号自有标题栏）。
2. **计算样式内联**：把与标签默认值不同的可见样式写入 `style`，并去掉 `class` / `id`。
3. **围栏改写**：见下。
4. **列表改写**：见下。
5. **行内 code 连字符**：`<code>` 文本中的 `-` 换成非断行连字符（U+2011），不加 `nowrap`。
6. **括号贴紧**：`strong` / `em` / `a` 后紧跟的「（…）」或「（…）：」与前一标签保持同一行（括号本身不加粗）。
7. **图片**：见下。
8. **元素间空格**：夹在两个元素兄弟之间的普通空格，复制后在公众号中仍应可见（避免 `</strong> <em>` 粘成一词）。
9. **根容器样式**：至少带上正文容器的字族、字号、行高、颜色、对齐、背景等。

纯文本后备：去掉文首 `h1` 后的可见文本，与 HTML 一并提供给剪贴板。

### 样式内联规则

**应拷贝的类别**：颜色与背景、字体相关、行高与字距、对齐与装饰、缩进与换行、`margin` / `padding`、边框与圆角、`display`、列表标记样式、垂直对齐、`max-width`、透明度等影响阅读呈现的属性。

**不应内联**：`height` / `width`（公众号字体与行宽和浏览器不一致，固定高度易行重叠）。

其它约束：

- 与同标签浏览器默认相同的值可省略；例外：`h1`–`h6` 的 `font-size` 即使等于 UA 默认也必须内联（公众号自有标题字号，省略后如 GFM 的 `h2:1.5rem` 会丢字号，粘贴后层级可能小于带内联的 `h3`）。
- 无意义值可省略（如多数 `none` / `normal`、零宽边框、透明背景）；`margin-left` / `margin-right: auto` 若用于居中则应保留意图（图片见下节，可不依赖 `auto`）。
- 公众号对 `overflow`、`box-shadow`、flex/grid 支持差：不依赖它们还原布局；`display: flex|grid`（及 inline 变体）应降为可预测的 `block` / `inline`。
- 颜色优先写成 `#rrggbb`（全透明可用 `transparent`）。
- 行内 `code` 不要用 `word-break: break-all`（避免把 `--css` 一类标识拆开）。

特殊节点：

| 节点 | 行为 |
| ---- | ---- |
| 脚本 / 样式元素 | 不进入复制结果 |
| 硬换行 `br` | 保留换行语义即可 |
| 任务列表 checkbox | 换成文本 `☐ ` / `☑ ` |
| 图片 | 见下节 |

### 图片

- 不拷贝像素宽高；限制最大宽度不超过容器，高度随内容。
- 复制结果中图片应大致水平居中，且不依赖公众号常剥掉的 `margin:auto`。

### 围栏代码

公众号常丢掉 `white-space:pre` 与依赖 pre 的换行。复制前应将围栏改成不依赖 pre 的结构，例如：

- 按行拆成块级行（可用段落 + 换行），保留多行与缩进观感。
- 有行号时，行号与代码同行展示。
- 背景、前景、圆角、等宽字体等从当前主题计算样式继承，缺省可贴近深色代码块风格。

### 列表

公众号常把 `li` 标记与首个子元素（如 `code` / `strong`）拆成两行。复制前应将 `ul` / `ol` 收成带文本前缀的段落：

- 无序：`•` 前缀
- 有序：`1.`、`2.`… 前缀

嵌套列表应仍可读（例如内层缩进）；不要依赖原生 list-marker。

### 剪贴板与反馈

- 优先同时提供 HTML 与纯文本。
- 在剪贴板 API 不可用时须有回退，尽量仍能复制 HTML。
- 成功 / 失败须有短暂可见反馈（如底部提示）。

### 与 003 的边界

| 职责 | Spec |
| ---- | ---- |
| type → tag/class、文档外壳、`#md-article`、磁盘不预写 `style=` | 003 |
| 浏览器按钮、内联与公众号改写、剪贴板 | **004（本文）** |

主题样式只通过计算样式影响复制结果；复制逻辑不应绑死某一主题色板（操作按钮与提示的外观除外）。

## Notes

- `file://` 下部分浏览器限制剪贴板写入；实现须有回退，调试时可用本地静态服务打开页面。
- 不要求把复杂 CSS（渐变、flex 原样布局等）完整带进公众号；以「可读、接近当前主题」为目标。
- 改内联范围或改写步骤时，同步更新本文与用户文档中的简要说明。
